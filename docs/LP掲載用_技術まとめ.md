## 2. 技術の中身（説明用の詳しい版）

LP に載せない細かい点も含めた一覧。LP の文を直すときの元にする。

### 画面と操作

| 技術 | どこで使っているか |
|---|---|
| JavaScript（ES Modules） | 画面・計算・音のすべて。外部のライブラリやフレームワークは使っていない（`package.json` に依存なし） |
| SVG | 三角形（木枠・角の金具・弦・ピン）、一弦の琴、五線譜（大譜表）、謎の弦、最終章の正方形（36＋36＝72）、鏡写しの説明の動き |
| Pointer Events | 辺をタップ・なぞって1音ずつ鳴らす、第1章の駒のドラッグとつまみの回転 |
| CSS（縦向き・横向き・低い横向き） | スマホ1画面に収める配置。紙芝居の巻物の字は絵の幅に合わせた大きさ（コンテナクエリの単位 cqw） |
| 色の演出 | 周波数から色相を決め、1オクターブ違う音は同じ色。和音は3色を混ぜる |

### 計算と判定

| 技術 | 内容 |
|---|---|
| 整数での判定 | 長さを「n」か「n√2」の組で持ち、閉じる・直角・同じ形を2乗した整数で比べる。和の比較も整数だけで符号を求める |
| 純正律と12平均律 | 根音（とベースライン）は12平均律、和音の中は根音から純正律で積む。七の和音・m7(♭5)・分数コードは、ベースとの関係で調律を決める |
| うなり（ビート） | お題と自分の音の周波数の差から揺れの速さを求める。第1章は、揺れが1秒に1回未満を1秒保つと合格 |
| 全数探索 | 長さ2〜24で閉じる三角形をすべて調べ、純正な三和音になるもの（20セント以内・最高音 C5 まで）を候補にする |
| 問題の生成と検査 | コード進行13種と光と影（第3章）から8小節を作る。おとりの棒の選び方（同じ音名の組を避ける・ひっかけを入れる・並びを混ぜる）をテストで検査 |
| シード付き乱数 | mulberry32。同じ種なら同じ問題になる（選択プレイはカノン進行・キーCで固定） |
| 鏡写し | 長調の三角形の周波数の比を、そのまま辺の比にすると平行調の短調になる（例 10・12・15 → 12・15・18）。2本は同じ棒 |

### 音（Web Audio API。すべてブラウザ内で合成）

| 音 | 作り方 |
|---|---|
| 弦（ガット弦） | FM音源（変調の倍率1と3）。はじいた瞬間だけ変調を深くして硬めのアタックにし、短い雑音でピックの感じを足す。高すぎる音を削り、胴の響き（220Hz あたり）を足す |
| 鐘 | FM音源（倍率1）に、2倍の「カン」と高い倍音（4・6・9倍）の「キラッ」と雑音を少し重ねる |
| 精霊の声 | グラスハープ：5セントずらした2つの音を重ねて、ゆらぎを出す |
| 曲（フレーズ・1曲） | 和音とベースラインを小節ごとに組み、裏拍で軽く刻む。8小節の1曲は9小節目に主和音を全音符で鳴らして締める |
| 出口の安全装置 | コンプレッサー（-3dB）で歪みを防ぐ。曲の音量は OfflineAudioContext で書き出して山の高さを測り、届かない大きさにした |

### 公開・保存・作り方

| 技術 | 内容 |
|---|---|
| PWA（Service Worker） | 版ごとのファイルを先に読み込み、通信なしでも遊べる。新しい版は「更新する」を押したときだけ切り替える |
| localStorage | 連続プレイの続き、発見の巻物、案内・序を見た記録、第1章の最速の記録、消音、結果を出すまでの待ち |
| GitHub Pages ＋ GitHub Actions | `main` へ送ると公開。独自ドメイン root.sikumilab.com。`build-info.json` に版とコミットを書き出し、公開を確かめる |
| テスト | Node の `node --test`（161件）。計算・判定・問題の生成・調律・曲・保存・画面の配置計算を検査 |
| 絵 | 画像生成AI（Codex に依頼）。WebP。三角形の木枠・金具・ピンは部品の絵をコードで組み立てる |
| 前作からの部品 | 曲の五線譜の描き方は koekit（サエズリズム）、画面の切り替えの待ちは PRISM NOTES の値、遊び方の段階と紙芝居の形は FLOAT NOTES にそろえた |
