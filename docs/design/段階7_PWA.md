# 段階7 設計メモ：PWA（通信なしで遊べる・更新の知らせ）

2026-11-14 作成。Codex からの引き継ぎ（`ROOT_NOTES_Claude引継ぎ_2026-11-14.md`）で、PWA は Claude の担当になった。実装指示書の段階7のうち、まず PWA（F-016）を作る。進み具合の保存（C-04・AC-07）と公開先（Cloudflare）は、7章で決めてもらう。

## 1. 目的と完了条件

- 一度開いたあとは、通信がなくても遊べる（F-016）
- 新しい版を公開したら、遊んでいる人に「新しい版を使えます」と知らせ、押すと切り替わる。勝手に切り替えて遊びを途切れさせない
- スマホのホーム画面に置ける（アプリのように開ける）
- 完了の確かめ：自動テスト、ブラウザで「通信を切って開き直しても遊べる」「版を上げると知らせが出て切り替わる」、発案者の実機（Pixel 9a）

AQUA の仕組み（ROOT も同じにする）：
- **版ごとの保存**：資材の一覧と、資材ごとの照合値（SHA-256）を、まとめるとき（build）に worker へ書き込む。準備のときは足りない資材だけを取り、取った中身を照合する。前の版に同じ中身があれば通信せずに使う（4件ずつ、1件60秒まで）
- **起動**：この版の資材がそろっていれば、入口のページも保存した物を使う（遅い通信でも待たない）。そろっていなければ通信し、つながらなければ前の版の保存、それもなければ案内のページ
- **切り替え**：画面の「更新する」で、資材がそろっているときだけ切り替える。直前の版の保存を1つ残す（ほかのタブが前の版を使っていても困らない）
- **開発中は動かさない**：worker の登録は、まとめた版（`index.html` に印を書き込んだもの）だけ。`npm run dev` では登録しない

## 4. 今の公開との関係

- 今は GitHub Pages（確認用）と独自ドメイン root.sikumilab.com で公開されている。入口の `index.html` は版のフォルダの外にあり、Pages が10分ほど前の版を返すことがある。worker が入ると、入口も版ごとに保存されるので、更新は「新しい版を使えます」の知らせで切り替わる形になる
- 一度 worker が入った端末は、以後は worker の版で動く。発案者が実機で確かめるときは、知らせの「更新する」を押す手順が増える

## 5. この段階で守ること

- 保存するのは遊ぶための資材だけ。進み具合（案内の記録など）は端末の localStorage のまま、worker では消さない（C-04）
- 採用前の素材（物語素材 v0.2.0、画面案 `ui-preview`）は組み込まない
- 表示の版と、読み込む場所（版のフォルダ）は、今までどおり版を上げるたびに変わる

4. 連続プレイの続きは、「連続プレイ」を押したとき「続きから／最初から」を選ぶ。発見の巻物は遊び方にかかわらずためる。選択プレイで灯した星は残す

## 9. 進み具合の保存（`src/game/progress.js`、キー `root-notes-progress-v1`）

前作の確認：AQUA は成績（少ない手数・連続プレイの最高）と案内の記録を保存し、遊んでいる途中の状態は残さない（`docs/data-model.md` D-06〜D-08a）。FLOAT も最高の記録と見た紙芝居だけ。ROOT は要件 AC-07（灯った星・発見・連続プレイの残り回数が再読み込み後も残る）があるので、途中から再開できる形にした。

| 保存する物 | 中身 | いつ保存 | いつ消える |
|---|---|---|---|
| `continuous` | 遊び方・今の章・第1章の灯った面・第2章の曲の設定（進行・キー・種・おとりの本数）と灯った星・失敗とメーターの残り | 面が灯る・回答・メーター・次の星・章が変わるたび | ゲームオーバー、最後まで通したとき、「最初から」を選んだとき |
| `select` | 選択プレイの第1章の面・第2章の星 | 灯るたび | 消さない（足すだけ） |
| `found` | 発見の巻物 | 見つけるたび | 消さない（足すだけ） |

- 曲は進行・キー・種・おとりの本数から作り直せる（`Play.snapshot`・`Play.restore`）。連続プレイは、灯っていない最初の星から再開
- 読めない記録は使わず、空の記録で上書きもしない（C-04）。保存できない端末でも遊べる
- 連続プレイの続きがあるときは、どの入口から連続プレイを始めても「続きから／最初から」を出す（勝手に上書きしない）
- チュートリアルは記録しない（練習のため）

## 11. アイコンの組み込み（2026-11-14、v0.9.10）

発案者がアイコンを B案（作品名＋NOTES＋木・真鍮・色の弦の三角形）で確定（Codex 素材 アイコン v1.0.0 の delivery。alternatives の A案は不採用）。

- `public/icon-192.png`（192×192）・`icon-512.png`（512×512）・`apple-touch-icon.png`（180×180）を、原本のまま置いた（SHA-256 一致。3枚とも RGB の PNG で透明の情報なし＝四隅まで不透明）
- まとめ（`scripts/build.js`）は今までどおり、3枚を版のフォルダの外に置き、マニフェスト（192・512）と入口のページ（`rel="icon"`・`rel="apple-touch-icon"`、各1つ）に入れる。3枚を版のフォルダへは写さないようにした（使わない写しが保存場所に二重に入っていた）
- 自動テスト：まとめの検査に、3枚が資材に入る・版のフォルダにない・マニフェストと入口のページの参照が1つずつ、を追加
- 確かめたこと（ブラウザ）：v0.9.8 の保存がある画面で「新しい版を使えます」→「更新する」で v0.9.10。新しい保存にアイコンが入り、`image/png` で返る。古い保存は直前の 0.9.8 だけ残る
- 未確認（実機）：Android の「インストール」が選べるか、ホーム画面のアイコンと起動の見え方、iPhone のホーム画面のアイコン
