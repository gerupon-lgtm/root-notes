## 4. フォルダの役割と、読み込みの向き

| フォルダ | 役割 | 読み込んでよいもの |
|---|---|---|
| `src/core/` | 計算と判定。**画面・音・保存に触れない**関数だけ | `content/` |
| `src/game/` | 遊びの進行と保存。画面に触れない | `core/`・`content/` |
| `src/content/` | データだけ。ほかを読み込まない | なし |
| `src/audio/` | Web Audio で鳴らす。受け取るのは周波数（Hz）と時刻だけ | なし |
| `src/ui/` | 描画と操作。ほかの部品を組み合わせる | すべて |

**なぜこう分けるか：** このゲームの土台は音と図形の計算（実装指示書3章）。計算を画面・音から切り離しておくと、Node のテストだけで要件5章の固定例や全進行・全キーの検査（C-03）を確かめられる。試作は1ファイルに計算と画面が混ざっていたので、本番ではここを分ける（実装指示書 1.3）。

`core/` が画面や音を読み込んでいないことは、段階1でテストにして守る【想定】。

## 6. 版数とテスト

- **版数の正典は `package.json`**（前作と同じ）。画面に出す版は `src/version.js` に書き、テストで一致を確かめる。ずれたらテストが落ちるので、上げ忘れに気づける。
- 初版は 0.1.0。上げ方は前作どおり：機能を足したら y を上げて z を0、直しは z を上げる。
- 段階0のテスト（`tests/foundation.test.js`）
  1. `package.json` の版と `APP_VERSION` が一致し、x.y.z の形である
  2. `index.html` に版数と © を差し込む場所がある
  3. `assets.js` の表に書いたパスのファイルが、すべて実在する（段階0は表が空なので、形だけ確かめる）

## 7. 絵の素材のパス（Codex との分担）

**いまの素材の状態（2026-11-14 確認）：** Codex は優先度1の候補（素材版 v0.1.0）を、リポジトリの**外**の `Z:\LLM Project\AQUA NOTES\ROOT_NOTES素材\v0.1.0\` に置いた。採用前の候補で、GitHub には入っていない（Codex の README と `docs/assets.md` に明記）。

- コード側でパスを書くのは `src/content/assets.js` の **1か所だけ**。画面のコードは名前で呼ぶ。
- 名前は Codex のファイル名にそろえる：`spirit-normal`・`spirit-listening`・`spirit-smiling`、`shield-sealed`・`shield-released`（剣 `sword-`・鎧 `armor-` も同じ）、`bell-12`・`bell-9`・`bell-8`・`bell-6`、`scene-forge-legend`。
- 段階0では、まだ採用前なので**素材を取り込まず、全部 `null`** にする。画面は仮の図形で描く。
- 採用が決まったら、Codex の推奨どおり `delivery/`（小さい版）の必要な画像をリポジトリの `public/art/` に写し、表にパスを書く。大きく見せる場面だけ `assets/` の版を使う。素材のフォルダは `ART_BASE` の1つの値なので、置き場所が変わっても1行で直せる。
- **鐘は4つを同じ倍率で表示する**（Codex の申し送り）。別々の枠に合わせて引き伸ばすと、12・9・8・6 の大きさの比が消えるため。段階6で守る。
- 段階0では Codex のフォルダに何も置かない・触らない。
