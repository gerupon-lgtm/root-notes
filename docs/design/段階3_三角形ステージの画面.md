## 3. 画面の配置

試作の配置を基準にする（要件7.1）。絵（Codex）はまだ採用前なので、星・三角形・棒は図形で描く。色は試作の夜空と金色を引き継ぐ（A区分。絵が来たら発案者・Codex と決め直す）。

### 3.1 縦向き（試作と同じ）

```
┌───────────────────────┐
│ ROOT NOTES  [ノーマル▾] ☰ │ ← 簡易ヘッダ（要件8.2）
│ ✦1 ✦2 ✦3 ✦4  ✦5 ✦6 ✦7 ✦8 │ ← 8つの星（8小節）
│ フレーズ1の2つ目   ◆◆◆◇◇ │ ← 位置と失敗の残り
│┌─────────────────────┐│
││                     ││
││      △ 三角形        ││ ← 画面の高さに合わせて伸縮
││                     ││
││ 揺れ 低● 中● 高●      ││
││ メッセージ           ││
│└─────────────────────┘│
│ [3] [8] [12] [15]       │ ← 棒（4列、2段）
│ [17] [20]               │
│ [お題] [和音] [比べる] [回答]│ ← 操作
└───────────────────────┘
```

### 3.2 横向き（新しく作る。案）

Pixel 9a の横向きは高さが約400px（ブラウザの帯を除くとさらに低い）。縦向きの並びを縦に積むと収まらないので、**左右2列**にする。

```
┌──────────────────────────────────────────┐
│ ROOT NOTES [ノーマル▾] ☰   ✦1 ✦2 ✦3 ✦4  ✦5 ✦6 ✦7 ✦8 │
│┌──────────────────┐  フレーズ1の2つ目  ◆◆◆◇◇ │
││                  │  [3] [8] [12] [15]         │
││    △ 三角形       │  [17] [20]                 │
││                  │                            │
││ 揺れ 低● 中● 高●   │  [お題] [和音] [比べる]     │
│└──────────────────┘  [  回答する  ]             │
└──────────────────────────────────────────┘
```

- 左＝三角形（なぞる場所を大きく取る）、右＝星・棒・操作。右手の親指で棒とボタンに届きやすい。
- PC の横長の画面も同じ2列にする（PC 対応。要件3章）。
- 向きを変えても、選んだ棒や進み具合はそのまま。

## 4. 遊び方の決まり（要件6.6。`src/content/modes.js`）

| | 選択プレイ | 連続・フリー | 連続・ノーマル | 連続・エキスパート |
|---|---|---|---|---|
| ステージ | カノン進行・キーC で固定 | 始めるたびに進行とキーをランダム | 同左 | 同左 |
| 失敗の上限（プレイ全体） | なし | なし | 10回【想定 Q-07】 | 5回【想定 Q-07】 |
| 回答前の自分の和音 | 鳴らせない | いつでも鳴らせる・比べられる | 鳴らせない | 鳴らせない |
| 揺れメーター | ボタンで表示、回数制限なし | 表示／非表示を選ぶ | プレイ全体で6回【想定】 | プレイ全体で3回【想定】 |
| おとりの棒 | 3本 | 3本 | 4本 | 5本 |

- おとりの本数は要件に記載がないので、試作の値を【想定】として置く。
- 失敗の上限は、閉じていない三角形の回答では減らない（要件5章）。使い切ったらゲームオーバー。
- メーターは閉じた三角形にだけ使え、棒を選び直すと消える。閉じていないときは使えず、回数も減らない（要件6.6）。
- 連続プレイは、灯したら次の星へ進む。選択プレイは、好きな星を選べる。

## 5. 音（`src/audio/`）

### 5.1 音色と準備

- 弦の音色：試作と同じ「のこぎり波1本＋高音を少し削る」。PRISM の strings（2本を±5セント）は自前のうなりが出るので使わない（Q-05 調査）。
- スマホは最初の操作まで音を出せないので、最初のタップで音を準備する（要件8章）。遅れの指定は前作と同じ30ミリ秒。
- 音を止めるときは、ごく短く小さくしてから止める（プツッという音を防ぐ。PRISM の `ownedVoice` の考え方）。

### 5.2 余韻の重ね方・止め方（要件6.5、AC-14）

| 場面 | 辺・棒の単音 | 理由 |
|---|---|---|
| 回答前（選択・ノーマル・エキスパート） | **次の単音が鳴ったら、前の単音を止める** | 速くなぞると和音が聞けてしまう抜け道を作らない |
| 回答後、連続・フリー | 前の単音を止めずに余韻を重ねる | なぞった順に和音が残る |
| お題の和音 | 単音を鳴らしても止めない | お題の和音を聞きながら、自分の1音を合わせられる。自分の音は1つしか鳴らないので、自分の和音は聞けない |

### 5.3 フレーズと1曲（AC-12、F-024）

- 試作と同じ形：1小節1.6秒【想定】、三角形の和音をジャランと鳴らし、裏拍で軽く刻む。ベースは小節の頭と半分で鳴らす。
- 4つの星（1〜4、5〜8）がそろうたびにそのフレーズを、8つそろったら1曲を流す。引き出しから、灯った和音でいつでも聴き直せる。
- 楽譜（いつ・どの高さ・どれだけ）を `src/game/song.js` で作り、小節の継ぎ目に隙間がないことを自動テストで確かめる。
- 曲の中で前の小節の余韻を残すかは、要件6.5で「聞き比べて決める【要確認】」。試作どおり（小節の中で終える）を既定にし、引き出しに「余韻を残す」切り替えを置いて、実機で聞き比べられるようにする。

## 6. 色・揺れメーター・消音でも分かる表示

- **色（F-008）**：周波数から色相を決め、1オクターブ違いは同じ色（試作と同じ式）。正解の和音では3辺の色を混ぜて三角形を光らせる【想定】。色が答えの手がかりになりすぎるかは実機で見る（要件11章、A区分）。
- **揺れメーター（F-007）**：低・中・高の3組それぞれに、点の明滅（揺れの速さで点滅）と「澄」「遠い」・数値を出す。
- **消音でも分かる（F-013、AC-06）**：閉じないときは三角形を破線の棒で描き「閉じない」と文で出す。正解は星が灯り、三角形が光る。不正解は画面が軽く揺れ、文で知らせる。揺れの大小は点の明滅と文字で分かる。

## 7. タイトルと画面の行き来

- タイトル（段階0の画面）に「三角形のステージ」を置き、遊ぶ画面へ進む。章立て（第1章〜最終章）は段階4以降で足す。
- 遊び方は、試作と同じくヘッダの切り替え（ノーマル▾）と引き出しで選ぶ。
- 引き出し：遊び方、今回の曲、発見の巻物、メーターの表示（フリー）、遊び方の説明、版と © SIKUMI LAB（要件8.2）。
- 発見と灯った星は、この段階では画面を閉じるまで覚えておくだけにする。端末への保存は段階7（C-04）。

**確認用の「答えを見る」**：試作にあった確認用のボタンを、URL の末尾に `?check` を付けたときだけ出す。フレーズと1曲（AC-12）を実機で早く確かめるため。通常の画面には出さない。

## 8. 自動テスト

| テスト | 中身 |
|---|---|
| 遊び方の決まり | 選択・ノーマル・エキスパートは回答前に和音を鳴らせない、フリーは鳴らせる（AC-05） |
| 失敗とメーター | プレイ全体で数える。閉じていない回答では減らない。使い切ったらゲームオーバー。メーターは閉じた三角形だけ（AC-05） |
| 余韻 | 場面ごとに「重ねる／止める」が 5.2 の表どおり（AC-14） |
| 楽譜 | フレーズは4小節、1曲は8小節。各小節にベースがあり、継ぎ目に隙間がない（AC-12） |
| 色 | 1オクターブ違いは同じ色 |
| 計算の核の境目 | `src/game/` も画面・音・保存に触れない（段階1のテストを広げる） |

画面は、アプリ内のブラウザで縦（412×923）・横（923×412）の大きさにして、スクロールが出ないこと、なぞりで音の関数が呼ばれることを確かめてから公開する。

## 9. 決めてほしいこと

1. **横向きの配置（3.2）**：左に三角形、右に星・棒・操作の2列でよいか。
2. **「回答後」の意味**：要件6.6の「回答するまで鳴らせない」の「回答後」を、**回答したその三角形が出ている間**とする案。棒を選び直したら回答前に戻る。理由：不正解の後も和音を鳴らせるままにすると、選択プレイで「わざと間違えて和音を聞く」抜け道になるため。回答した瞬間には、正誤にかかわらずその和音を鳴らす（試作と同じ）。

## 10. 段階3でしないこと

- 章立て（第2章・第3章の面の構成、1オクターブ違いの発見用のステージ）→ 段階4以降で相談
- 同じ三角形が続く件（段階2で確認：カノン進行で 6·10·15 が3回）→ 実機で気になれば直す
- 保存、通信なしで遊ぶ仕組み → 段階7
- 救済（ヒント、Q-03）→ 後で

## 13. 実機テストの指摘による直し（2026-11-14、v0.5.0）

発案者が Pixel 9a で v0.4.0 を試して出した指摘と、直したこと。

| 指摘 | 直したこと |
|---|---|
| ステージ開始時に「お題を聞く」をフラッシュさせて導線を明確に | 星に入るたびに「お題を聞く」を2回光らせる（前作 AQUA の開始の合図と同じ：0.7秒待って、0.7秒の光を0.35秒あけて2回）。お題を一度聞くまで金色の縁を残す |
| 三角形ができたら「回答する」を活性化 | 閉じた三角形ができるまで押せない（灰色）。できたら金色 |
| 和音を FM のストリングス・オルガン・エレピ系などで | `src/content/timbres.js`。値は前作から：オルガン・ブラス・ベース＝twist の fm-presets、エレピ＝PRISM・koekit の fm-piano、ストリングス＝koekit の strings。2本をずらして重ねる処理と歪みは外した（自前のうなりが、お題とのうなりの聞き分けを邪魔するため） |
| ステージごとに違う音色、フレーズは同じ音色、ベースは別の音色 | 星ごとにストリングス → オルガン → エレピ → ブラスの順に回す（隣の星は必ず違う）。お題・辺の単音・自分の和音は、そのステージの音色でそろえる（聞き比べのため）。フレーズと1曲は和音をエレピ1つで通し、ベースは FM ベース。曲の音色の選び方は解釈（下の「確認したいこと」） |
| クリア時・不成立時に結果のトースト、トーストで次のステージへの導線 | 前作 AQUA・PRISM と同じ形：操作欄に重ねて出し、×・外に触れる・Esc で閉じる。正解「澄んだ！」＋「次の星へ ▶」（選択プレイは「この星に残る」も）、不正解「違う響き」＋失敗の残り＋「もう一度」、ゲームオーバー、1曲できあがり（「新しい曲で遊ぶ」「タイトルへ」）。連続プレイは自動で進まず、トーストか「次の星へ」ボタンで進む。フレーズや1曲がそろったときは、流し終えてからトーストを出す |
| 三角形のスペースを減らして、操作するものを大きく | 棒・ボタンを高さ62px（縦に余裕がある縦向きは74px）、棒の数字を大きく。三角形の場所は残りの高さで縮む（Pixel 9a の縦で約520px） |

**確認したいこと：** 「フレーズとして鳴らすときは同じ音色」を「フレーズと1曲は、小節ごとに変えず1つの曲用の音色（いまはエレピ）で通す」と解釈した。

## 14. 実機テストの指摘による直し・その2（2026-11-14、v0.6.0）

| 指摘 | 直したこと |
|---|---|
| お題を聞く押下後に、パーツリストの周りをフラッシュ | お題を初めて聞いたら（棒をまだ3本選んでいなければ）棒の並びを2回光らせる |
| 他にも導線が必要な部分を探して対応 | 3本で閉じたら三角形（辺をなぞって確かめる）、閉じなければ棒の並び（選び直す）、不正解のトーストを閉じたら「お題を聞く」（聞き直して比べる）、正解のトーストを進まずに閉じたら「次の星へ」、ゲームオーバーのトーストを閉じたら「最初から」。一度に光らせるのは1か所。動きを減らす設定では、光らせずに金色の縁を2秒出す |
| 「澄んだ！」を別の表現に | 「星が灯った」（星を灯す遊びに合わせた。1か所で変えられる） |
| 「1小節目は「Ⅰ」」にコードネームを追加。相対名でも書き、進行の気づきに | 「1小節目は I ＝ D（キー D）」。フレーズや1曲がそろったときは「度数：I → V → …」「コード：D → A → …」の2行。曲を流している間・引き出しの「今回の曲」も同じ |

**コードネームの綴り：** キーの音階の文字で綴る（例：キー F♯ の VII は F でなく E♯、キー E の IIIm は G♯m）。キーの名前は、C♯ でなく D♭（よく使う綴り）に改めた。`src/core/harmony.js` の `chordName`、テストあり。

## 15. 五線譜（2026-11-14 発案者の追加、v0.7.0）

**指示：** コード進行を鳴らすタイミングで、五線譜に沿って、鳴っている音符を見せたい。参考は koekit サエズリズムの五線譜（`probe/saezuri/score.js`）。

| 決めたこと | 中身 |

## 17. 音のブツっという音と和音の歪み（2026-11-14、v0.8.12）

発案者の実機の指摘：「棒を選んで音を止めるとき、変わらずブツっと鳴る」「和音が少し歪む。音量を下げても歪む」。音を書き出して（OfflineAudioContext）数字で確かめてから直した。

**ブツっという音（不具合）：** v0.8.9 で入れた 0.05秒のフェードアウトは、働いていなかった。`cancelAndHoldAtTime` のあとに直線で下げると、Chrome では音量がその場（5ミリ秒以内）で0に落ちていた。`cancelScheduledValues` で予定を消し、今の音量から0.05秒かけて下げる書き方に直した。直したあと、止めた瞬間に出ていた高い音（4kHz より上）の山は、ベース +16.6dB → −1.1dB、エレピ +10.9dB → −4.9dB など、どの音色も保っている間と同じくらいになった。

**自然に消えるとき（発案者：0.04秒にやわらげる）：** オルガンとベースは、試聴の1.1秒が終わったあと約0.02秒で消えていた（消え方の時定数 0.012・0.015秒）。2つとも 0.04秒にした（`src/content/timbres.js`）。ブラス（0.03秒）は変えていない。

**和音の歪み（発案者：安全装置だけにする）：** 調律ではなく、出口のコンプレッサーが原因だった。初期設定（−24dB から 12:1 で押さえる）のままで、3音の和音でもいつも強くかかり、波の形が崩れていた。曲で −25dB（約6%）の歪み。音の中で起きているので、端末の音量を下げても残る。−3dB を超えたときだけ 20:1 で押さえる設定にした（`src/audio/engine.js` の `LIMITER`）。曲を通しても歪みはなく（−143dB）、一番大きいところは上限の約9割。全体の音量は前と1〜2dB しか違わない。

**未確認：** 実機（Pixel 9a）で、ブツっという音と歪みが消えたと感じられるか。

**プレイ画面の見た目（発案者：先に Codex に依頼）：** 深緑のトンマナと「三角の木枠の内側に弦を張った楽器」は、Codex に部品の素材を頼んでから作る。三角形の形は選んだ棒の長さで毎回変わるので、1枚の絵では描けない。枠と弦はコードで描き、Codex には伸ばして使える木目・角の金具・背景のような部品をお願いする（依頼文：リポジトリの外 `request-codex-play-ROOT.md`）。

## 18. 七の和音の置き方（2026-11-14、v0.8.13。要件 v0.19）

発案者の実機の指摘：「和音の歪みは残っている。F♯m7 などがすごく気になる」。v0.8.12 で直したコンプレッサーの歪みとは別に、**七の和音でベースと三角形がうなっていた**。

- 仕組み：七の和音は「三角形の三和音＋ベース」（例 F♯m7 ＝ 三角形 A·C♯·E ＋ ベース F♯）。三角形の根音（A）を平均律に置いていたので、ベースから見た和音の5度が純正からずれていた（全進行を計算：m7 −16c、maj7 +14c、属七 −35c）。
- 直し（発案者：置き直す）：和音の根音であるベースを平均律に置き、三角形をベースから見て純正になる高さへずらす（`src/core/stage-gen.js` の `SEVENTH_TUNING`。ステージに `tuneCents` を持たせた）。m7 は 316c・702c・1018c、maj7 は 386c・702c・1088c で全体が純正。

- 変えないもの：m7(♭5)（今の置き方のほうがずれが小さい）、ふつうの三和音。
- 分数コード（発案者：A ベースを合わせる）：ベースが和音の3度のとき（G/B・C/E など）、三角形の3度は平均律から約14セント低く、平均律のベースとオクターブ違いで毎秒2〜3回うなっていた。三角形（和音の根音）は平均律のまま、その小節のベースだけを三角形の3度にちょうど合わせる（ステージの `bassCents`、`src/game/song.js` で使う）。クリシェの下降ベースは B・E が14セント低くなり、キーCの純正律の音階（15/8・5/4）と同じ並びになる。ベースが5度（C/G）はずれが2セントなので動かさない。

- 自動テスト：機械検査で、全進行×12キーの七の和音（maj7 144・m7 132・属七 120 小節）がベースから見て純正（属七は3度と5度のずれが同じ大きさ）であることを確かめる。
