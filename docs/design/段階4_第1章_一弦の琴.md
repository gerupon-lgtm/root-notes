## 3. ゲームの流れ（骨組み）

```
タイトル
 ├ 連続プレイ（フリー／ノーマル／エキスパート）
 │   序 → 第1章 一弦の琴（5面）→〔章末の謎：盾〕→ 第2章 三角形（8つの星）→〔謎：剣〕→〔第3章〕→〔謎：鎧〕→〔最終章〕
 └ 選択プレイ
     章を選ぶ（第1章／第2章）→ その章の面を選ぶ
```

- 〔 〕は、この段階では中身のない仮の1画面（「この先は準備中」と、次へ進むボタン）。謎と最終章は段階5、序の絵とセリフは段階6で作る。
- 序は、この段階では文字だけの仮の画面にする（6.10 の8場面の見出しを並べ、「はじめる」で第1章へ）。2回目からは飛ばせる（6.10）。
- 失敗の上限・メーターの回数は、プレイ全体で数える決まり（6.6）なので、章をまたいでも引き継ぐ。

## 12. 実機テストの指摘による直し：画面が動く件と、駒の持ち手（2026-11-14、未公開。Codex の作業が終わってから公開）

発案者の指摘：「チュートリアルで、駒の説明の画面に触れたら、次の画面の位置が急に変わる」「指で駒を動かすと位置が隠れて見づらい。PRISM などを参考に、オフセットした位置から操作できるように。駒から少し下にもつかめるものを付けて、画面上の位置を見ながら操作できるように。駒自体でも移動できるように」。

**PRISM の確認**：案内の欄は本文3行・補足2行の高さを先に確保し、文の切り替えで盤面を動かさない（`docs/reviews/2026-11-06-tutorial-discovery.md`）。指で隠れる所は、指から離れた上側に拡大窓を出して見せる（`src/ui/magnifier.js`、`docs/reviews/2026-10-18-*`）。今回は発案者のイメージ（駒の下の持ち手）で作った。

**原因**：駒に触れて動かした瞬間に、案内が次の手順へ切り替わり、文の長さで帯の高さが変わって、盤面ごと駒が動いていた。

**直し**（Codex の作業中のため、Codex が触らないファイルだけを変えた：`src/ui/monochord-screen.js`・`src/content/tutorial.js`）
- 帯の文と補足の高さを先に確保（文 2行・補足 2行）し、一度広がった高さは縮めない。画面の大きさが変わったときだけ数え直す。CSS ではなく画面のコードで指定した（`style.css` を Codex が触る可能性があるため。あとで CSS へ移してよい）
- 駒やつまみを触っている間は、次の手順へ切り替えない。指を離したときに進める
- 駒の下に持ち手：駒から軸を下へ伸ばし、胴と目盛りより下（弦から 86 下）に丸い持ち手（既存の真鍮の金具の絵。新しい絵は作っていない）。持ち手でも駒そのものでもつかめる。つかんだ所と駒の差を保つので、つかんだ瞬間に駒が飛ばない。弦をはじくタップは、駒より左の弦の近くだけ
- 案内の手順3の文を「駒の下の持ち手を、指で左右に動かそう」に、指先の輪のお手本を持ち手の上に
- 今の面の比の印（金の点線と文字）は、合格前も合格後も出さない（合格後は駒の上の緑の比と重なっていた）

## 15. チュートリアルをチューニングの順番に（2026-11-14、v0.9.11）

発案者：「お題を聞く → はじく → 重ねて聞く → スライドを動かす、で進めたい。完全にギターのチューニング。ギターを知らない人にも伝わるように。間に『なにをやっているか』に触れて理解を深める設計に」「きれいな和音は揺れが感じづらいので、一つにまとまるというニュアンスを含めて」。
