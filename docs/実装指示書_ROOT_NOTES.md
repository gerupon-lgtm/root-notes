## 4. 共有する決まり（担当が変わっても守る契約）

| 項目 | 決まり | 根拠 |
|---|---|---|
| 音の高さ | f ＝ K ÷ 長さ。Kは星ごと、1ステージの中では固定。張りで変えない | C-01、5章 |
| 長さの持ち方 | 整数部分と√2の有無の組。比べるときもこの組のまま。√2の辺に許容差を使わない | 5章 |
| 閉じる条件 | 短い2本の和 ＞ 最長。等しいときは閉じない | 5章 |
| 正解 | 長さの組が一致（順不同）。1オクターブ違いは不正解 | 5章 |
| 和音を鳴らせる場面 | 連続・フリーはいつでも。選択プレイ・ノーマル・エキスパートは回答後だけ | 6.6 |
| 余韻 | 回答後と連続・フリーは、前の音を止めずに重ねる。回答前は、次の音で前の音を止める。PRISMの「0.5秒未満は直前の高さにそろえる」決まりは持ち込まない | 6.5、AC-14 |
| 謎の正誤 | 謎の場面では正誤を示さない。封音の反応も、選んだ弦に左右させない | 6.3 |
| ZAP | 足りない辺の元の謎にだけ戻る。解き直した後、最終章を初めから。ZAPごとに失敗上限を1つ使う | 6.4 |
| 音色 | 遊ぶ部分の弦は、倍音が整数倍に並ぶ音色。物語の鐘は PRISM の鐘の音色（√2のFM）。聴感で変えてよい | 6.9、7.1 |
| 保存 | 端末の中だけ。無断で消さない、サーバーへ送らない | C-04 |
| 日時 | 今の要件に日時の入力・表示はない。保存日時を持つ場合は、世界標準時（UTC）で保存し、端末の時刻で表示する（取れない場合は日本時間） | 8.1 |
| 伝承と創作 | 伝承を事実として示さない。鐘・封音・教団・精霊はゲームの創作 | C-05 |

## 5. 変えてよい範囲と、仕様が成り立たないとき

- 要件定義書0章に従います。配置・文言・色・演出・音色（A）は、発案者の指示ですぐ変えてかまいません。機能や既定値（B）は、変えたら要件定義書の該当行と改訂履歴を更新します。C-01〜C-05 は、発案者と改訂内容を合意してから変えます。
- 実装中に「決まっていた要件が成り立たない」と分かったら、要件定義書を黙って書き換えないでください。発案者に報告し、合意した後で、該当行に【失効】（行を消さず、取り消し線と失効日・理由・置き換え先を書く）を付け、改訂履歴に1行追記します。
- 技術的に難しいという理由で、確かめる対象を独断で外さないでください（C-02）。難しい場合は、根拠を示して相談してください。

## 6. 区切りと報告

- **commit**：各段階の終わり、または発案者の指示があったとき。
- **push**：発案者が指示したときだけ。段階が終わったことだけを理由に push しない。
- **報告**：日本語で書く。各段階の終わりに、次をまとめる。
  - 作ったもの・変えたファイル
  - 確認済みのこと（実行したテストと結果）と、未確認のこと（実機で見ていない画面など）を分ける
  - 決まっていないことに触れた箇所と、仮に置いた形
  - 次の段階で発案者に決めてほしいこと（2〜3個に絞る）
- 自動テストの成功を、発案者の聴感・見た目の確認の代わりにしない。音とスマホの画面は、発案者が確認端末（Pixel 6a・iPhone XR）で確かめる。
